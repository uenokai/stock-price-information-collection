# stock-price-information-collection

中長期投資向けの銘柄発掘システム。**大目的は投資リターンの最大化**なので、最上位の評価指標は「指数ETFに勝てるか」に置く。

1. **何を買うか**: 財務指標 (ROE・成長率・PER等) と株価上昇率を業種内で相対評価し、上位60銘柄の候補リストを週次で作る
2. **過去検証**: 同じ選び方を過去に当てた場合の成績を指数ETF (SPY / 1306.T) と比べる (週次)
3. **仮の運用**: 戦略に従うと「今なにを持つか」を具体的な銘柄リストにし、月初に入れ替え、評価額を指数と並べて日次で記録する。過去検証では測れない「その後の成績」がここに溜まる
4. **参考情報**: 候補リスト銘柄の値動きの条件 (押し目等) を日次で判定する。過去検証では買う日を決める価値がほぼ無いと分かったので、売買の引き金ではなく参考表示

```
[対象銘柄すべて (約220銘柄: 日本株+米国株)]
      │  週次: 財務指標 + 株価上昇率 を業種内の順位で合成
      ▼
[候補リスト (上位60銘柄)] ─┬─ 週次: 保有銘柄の過去検証 (上位N銘柄の月次保有 vs 指数ETF)
      │                        │     → reports/portfolio-backtest.md  ← 指数に勝てなければ指数ETFを買う
      │                        └─ 日次: 仮の運用 (市場別 上位15 × 2戦略を等金額保有、月初に入れ替え)
      │                              → reports/model-portfolio.md    ← 今なにを持つか + その後の成績 vs 指数
      │  日次: 値動きの条件の判定 (参考情報)
      ▼
[reports/latest-signals.md] ──→ data/signal_log.csv に記録
                                    │  日次: +20/+60/+120 営業日後リターンを集計
                                    ▼
                              [reports/performance.md]
```

出力はすべて Markdown でリポジトリにコミットされる。通知は現在行わない (Slack Webhook を設定しない限り何も送らない)。Obsidian で読む場合は vault 内にこのリポジトリを clone するか Obsidian Git プラグインで pull し、[reports/index.md](reports/index.md) を入口にする。

詳細な設計は [docs/system-design.md](docs/system-design.md) を参照。

## 自動実行 (GitHub Actions)

| ワークフロー | スケジュール | 内容 |
|---|---|---|
| [Weekly Screening](.github/workflows/weekly-screen.yml) | 毎週土曜 07:00 JST | 対象銘柄すべてを絞り込みし `data/watchlist.csv` と `reports/watchlist.md` を更新。財務記録を `data/fundamentals/` に保存。続けて合図の過去検証 (`reports/backtest.md`) と保有銘柄の過去検証 (`reports/portfolio-backtest.md`) を更新 |
| [Daily Signals](.github/workflows/daily-signals.yml) | 平日 08:00 JST | 候補リストの値動きの条件を判定し `reports/latest-signals.md` を更新。成立合図を `data/signal_log.csv` に記録し、過去の合図の成績 `reports/performance.md` を更新。仮の運用を評価し (月初なら入れ替え) `reports/model-portfolio.md` を更新 |
| [Tests](.github/workflows/tests.yml) | push / PR 時 | 単体・統合テスト |

- どちらも **Actions タブから手動実行 (workflow_dispatch) 可能**。初回はまず Weekly Screening を手動実行すると候補リストが生成される (Daily Signals は候補リスト未生成なら自動で絞り込みも実行する)。
- スケジュール実行はリポジトリの**デフォルトブランチにマージされてから**有効になる。
- **注意: GitHub は 60 日間コミットが無いリポジトリのスケジュール実行を自動停止する。** 結果コミットが毎日入っていれば止まらないが、止まった場合は Actions タブで各ワークフローを "Enable workflow" する。
- ワークフロー失敗時は `SLACK_WEBHOOK_URL` が設定されていれば Slack に失敗通知が届く。

### 通知 (現在はオフ)

通知は行わず、Markdown レポートの蓄積のみ。将来通知したくなったら、リポジトリの Settings → Secrets and variables → Actions に `SLACK_WEBHOOK_URL` を登録すると新規合図の成立時とワークフロー失敗時に Slack へ送る。新規 = 同じ銘柄・同じ合図が直近10営業日に出ていなかったもの (`config.yaml` の `signals.renotify_after_days`)。

## ローカルでの実行

```bash
pip install -e ".[dev]"

# 週次: 絞り込み → 候補リスト生成 (全銘柄で5分前後)
stock-screener screen
stock-screener screen --limit 20          # 動作確認用に銘柄数を絞る

# 日次: 買いの合図判定 → 台帳記録 → 成績表更新 → レポート生成
stock-screener signals                    # Slack通知あり (SLACK_WEBHOOK_URL 設定時)
stock-screener signals --no-notify

# 保有銘柄の過去検証: 毎月上位N銘柄を等金額保有した場合 vs 指数ETF (過去10年)
stock-screener portfolio
stock-screener portfolio --period 15y

# 仮の運用: 評価と月初の入れ替え → reports/model-portfolio.md
stock-screener model-portfolio
stock-screener model-portfolio --rebalance   # 月が変わっていなくても入れ替える

# 合図ごとの過去検証: 本番と同じルールを過去5年に適用して成績を集計
stock-screener backtest                   # 現在の候補リストが対象
stock-screener backtest --universe        # 対象銘柄すべてが対象 (選定の偏りを減らしたい場合)

# テスト
python -m pytest
```

### 4つの検証の違い

- **model-portfolio.md** は「これから」の成績。開始後の実際の値動きで決まるので後から選んだ銘柄ではなく、過去検証の弱点 (生存者の偏り) が無い。半年〜1年分溜まったら、指数との差がプラスかで戦略を続けるか判断する
- **portfolio-backtest.md** は「過去」の成績。戦略としての成績 (年平均リターン・最大下落率) を指数ETFと比べる。価格だけで決まる基準 (株価上昇率・傾向) は過去10年で検証済み。財務指標による基準は過去時点の値が無いため、`data/fundamentals/` が1年以上溜まってから検証する
- **backtest.md** は値動きの合図1件ごとの N営業日後リターン。全営業日に買った場合との差 (超過) がほぼゼロ = タイミングの価値なし、が現時点の結果
- **performance.md** は実際に出した合図の追跡。記録が溜まるまで (目安30件以上) は参考値
- いずれも終値ベースの単純比較。保有銘柄の過去検証のみ入れ替え手数料 (往復0.2%) を控除。税金・為替は未考慮

### 現時点の結論 (2026-10-20, 詳細は reports/)

- 株価上昇率上位15銘柄の月次保有は、日本・米国とも指数ETFと全銘柄の等金額を上回った (日本 年平均リターン +24% vs 指数 +12%、米国 +22% vs +15%)。値動きの大きさは 1.5 倍になる
- 200日線の上昇傾向の絞り込みは、リターンを下げる代わりに最大下落率をわずかに改善する程度
- 値動きの4つの合図は買う日を決める根拠にならない
- この結果を受けて、週次絞り込みの総合点に株価上昇率を重み 0.22 で加えた (`config.yaml`)

## カスタマイズ

- **監視銘柄の追加・削除**: `data/universe/japan.csv` / `data/universe/us.csv` を編集 (ticker は yfinance 形式。例: `7203.T`, `AAPL`, `0700.HK`)。別市場を足す場合は CSV を追加して `config.yaml` の `universe:` に登録する。
- **点数の重み・候補リスト銘柄数・合図の閾値・新規判定の間隔・成績の評価期間**: すべて [config.yaml](config.yaml) で調整可能。

## 用語の対応表

このプロジェクトでは、専門用語を次の言葉に置き換えて書いている。ネットで調べるときは右の言葉を使う。

| このプロジェクトでの言葉 | 意味 | 一般的な専門用語 |
|---|---|---|
| 株価上昇率 | 1年前から1か月前までの株価の上昇率 | モメンタム |
| 上昇率戦略 | 株価上昇率が高い順に、日本15銘柄と米国15銘柄を持つ方法 | モメンタム戦略 |
| 総合点 | 財務指標8つと株価上昇率を、業種内の順位にして重み付きで平均した0から1の点数 | 合成スコア |
| 総合点戦略 | 総合点が高い順に、日本15銘柄と米国15銘柄を持つ方法 | 合成スコア戦略 |
| 財務指標 | ROE、営業利益率、売上成長率、利益成長率、PER、PBR、配当利回り、負債比率 | ファンダメンタル指標 |
| 仮の運用 | お金を使わず、戦略に従った場合の保有と成績を記録すること | ペーパートレード、モデルポートフォリオ |
| 過去検証 | 過去の株価に同じ方法を当てはめて成績を見ること | バックテスト |
| 保有銘柄の過去検証 | 毎月上位15銘柄を持った場合の過去の成績を、指数ETFと比べたもの | ポートフォリオ・バックテスト |
| 合図 | ゴールデンクロスなど、株価の値動きから出る買いのきっかけ。買う日を決める根拠にはならなかった | シグナル |
| 候補リスト | 総合点が高い上位60銘柄 | ウォッチリスト |
| 対象銘柄 | システムが調べる222銘柄 | ユニバース |
| 指数との差 | 戦略の年平均リターンから、指数ETFの年平均リターンを引いたもの | 超過リターン |
| 比較基準 | 全営業日に買った場合の平均 | ベースライン |
| 入れ替え | 月初に持つ銘柄を組み直すこと | リバランス |
| 順位 | 同じ業種の中で何番目か。0から1で表し、1に近いほど上位 | パーセンタイル |
| 生存者の偏り | 今も上場している銘柄だけを対象にしたため、過去の成績が実際より良く見えること | 生存バイアス |
| 値動きの大きさ | 年率での値動きの幅。大きいほど上下に振れる | ボラティリティ |
| 最大下落率 | 評価額が最高値から最も下がった割合 | 最大ドローダウン |
| リターン効率 | 値動きの大きさに対して、どれだけ増えたか | シャープレシオ |

## 構成

```
src/stock_screener/
├── cli.py                  # コマンドラインエントリポイント (screen / signals / backtest)
├── config.py               # config.yaml の読み込み
├── universe.py             # 対象銘柄CSVの読み込み
├── data/
│   ├── prices.py           # 株価履歴の取得 (yfinance + 期間別Parquetキャッシュ)
│   └── fundamentals.py     # 財務指標の取得 (yfinance)
├── screening/
│   └── fundamental.py      # 業種内の順位による総合点付け
├── signals/
│   ├── indicators.py       # SMA / RSI (Wilder) / 期間高値
│   └── technical.py        # 値動きの条件の判定 (全営業日ベクトル計算。日次判定と過去検証で共用)
├── tracking.py             # 合図台帳の更新と N営業日後リターンの集計
├── backtest.py             # 合図ごとの過去検証 (比較基準比較付き)
├── portfolio.py            # 保有銘柄の過去検証 (月次上位N保有 vs 指数ETF) と株価上昇率計算
├── model_portfolio.py      # 仮の運用: 選定・等金額入れ替え・日次評価・状態CSV
├── report.py               # Markdownレポート生成
└── notify.py               # Slack通知
```

## 使い方 (運用の流れ)

見るのは `reports/model-portfolio.md` の1ファイルだけ。

1. 月に1回、月初の最初の平日の翌日以降に `model-portfolio.md` を開く。「成績」の表で指数との差がプラスかを見る
2. 「直近の入れ替え」の買い・売りが、戦略に従う場合の売買指示に相当する (自動では発注しない)
3. 他のレポートは必要なときだけ。`reports/index.md` に用途を一覧してある
4. 半年〜1年経って指数との差がマイナスなら、戦略を見直すか指数ETFに切り替える

## 免責事項

本システムは機械的な絞り込み・合図判定の結果を提示するものであり、投資助言ではなく、利益を保証するものでもありません。投資判断は必ずご自身の責任で行ってください。また、無料データソース (yfinance) を利用しているため、データの遅延・欠損・仕様変更が起こり得ます。
