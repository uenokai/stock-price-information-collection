# 銘柄発掘システム 設計書

中長期投資(数ヶ月〜年単位)を対象に、「儲けられる可能性が高い銘柄」を「適切なタイミング」で発見するためのシステム設計。

## 大目的と評価指標

大目的は**投資リターンの最大化**。したがってシステムの良し悪しは「指数ETF (SPY / TOPIX連動ETF) を買って持ち続けた場合に勝てるか」で判断する。指数に勝てない選び方には価値が無く、その場合の最善手は指数ETFを買うことである。

- 最上位の指標: ポートフォリオ・バックテスト (`reports/portfolio-backtest.md`) の「対指数」CAGR と最大ドローダウン
- ルールはすべて過去データで検証してから採用する。検証できないルール (過去時点のデータが無い) は「未検証」と明記する
- 通知は目的ではないので当面行わない。出力は Markdown でリポジトリに蓄積し、Obsidian 等から読む

## 基本コンセプト: 2段階スクリーニング

「良い銘柄を見つけること」と「良いタイミングを見つけること」は別の問題なので、役割を分けて2段階で処理する。

```
[全上場銘柄 (数千)]
      │
      ▼  第1段階: ファンダメンタル・スクリーニング (週次)
      │   → 業績・割安性・財務健全性でスコアリング
      ▼
[ウォッチリスト (50〜100銘柄)]
      │
      ▼  第2段階: テクニカル・タイミング判定 (日次)
      │   → チャートシグナルで「今が買い場か」を判定
      ▼
[買い候補 (0〜数銘柄/日)] ──→ 通知・レポート
```

- **第1段階(何を買うか)**: 全銘柄から「良い会社なのに割安」な銘柄を機械的に絞り込む。中長期ではここが収益の源泉。
- **第2段階(いつ買うか)**: 絞り込んだ銘柄だけを毎日監視し、トレンド転換や押し目などの買いシグナルが出た瞬間に通知する。「良い銘柄でも高値掴みしない」ための仕組み。

## モジュール詳細

### ① データ収集層

| データ | ソース | 費用 | 対応市場 |
|---|---|---|---|
| 株価 (日足OHLCV) | yfinance | 無料 | 日・米・欧・アジアほぼ全市場 |
| 財務指標 (PER/PBR/ROE等) | yfinance (`Ticker.info`, financials) | 無料 | 同上 |
| 日本株の詳細財務・信用残 | J-Quants API | 無料枠あり(12週遅延) / ライトプラン月1,650円 | 日本 |
| 為替レート | yfinance | 無料 | — |

- **多市場対応の方針**: ティッカーの管理を「銘柄コード + 市場サフィックス」(例: `7203.T`, `AAPL`, `0700.HK`)で統一し、市場ごとの差異(通貨・営業日)はデータ収集層で吸収する。
- 日次バッチで差分取得し、データストアに追記。

### ② ファンダメンタル・スクリーニング (週次)

各銘柄を以下の観点でスコアリングし、上位銘柄をウォッチリストへ。

| カテゴリ | 指標例 | 見るポイント |
|---|---|---|
| 収益性 | ROE、営業利益率 | 稼ぐ力が高いか |
| 成長性 | 売上・営業利益の成長率(3年) | 伸びているか |
| 割安性 | PER、PBR、配当利回り | 同業種比で割安か |
| 健全性 | 自己資本比率、有利子負債 | 財務が安全か |
| モメンタム | 12-1ヶ月の株価騰落率 | 直近1年 (直近1ヶ月を除く) で上がっているか。ポートフォリオ・バックテストで効果を確認済み |

- 指標は**業種内での相対順位(パーセンタイル)**に変換してから合成スコア化する(業種によって適正PERが違うため)。
- スコア閾値・重みは設定ファイル(`config.yaml`)で調整可能にする。

### ③ テクニカル・タイミング判定 (日次) — 参考情報に格下げ

ウォッチリスト銘柄に対して、中長期投資に適したシグナルのみを判定する。**ただし 2026-10 のバックテストで、4シグナルとも全営業日に買った場合との差が ±1% 以内と分かった**ため、売買の引き金ではなく参考情報として扱う (判定・記録・成績追跡は続け、証拠が溜まったら再評価する)。

- **ゴールデンクロス**: 50日移動平均が200日移動平均を上抜け(長期トレンド転換)
- **52週高値ブレイク**: 出来高を伴う新高値更新(上昇トレンド入り)
- **押し目**: 上昇トレンド中(株価 > 200日線)で RSI が30〜40台まで調整
- **出来高急増**: 平常時の2〜3倍以上の出来高(注目度の変化)

複数シグナルの同時成立を高信頼度として扱う。

### ④ データストア

- 株価履歴: **Parquet** ファイル(列指向で高速・省スペース)
- スクリーニング結果・シグナル履歴: **SQLite**
- どちらもファイルベースなのでサーバ不要。履歴はリポジトリまたは GitHub Actions のキャッシュ/アーティファクトで保持。

### ⑤ レポート・通知

- 日次で Markdown レポートを自動生成し、リポジトリにコミット(いつでも GitHub 上で閲覧可能)
- 通知は当面行わない (決定事項: 2026-10-20。Slack は手段として不適、Obsidian は通知機能を持たないため、Markdown の蓄積のみとする)。`SLACK_WEBHOOK_URL` を設定すれば新規シグナル時とワークフロー失敗時に Slack へ送る仕組みは残してある

### ⑥ バックテスト + 成績追跡 (Phase 3: 実装済み)

「検証せずにルールを信じない」ための仕組みを3本立てで持つ。

| 仕組み | 入力 | 出力 | 実行 |
|---|---|---|---|
| **ポートフォリオ・バックテスト** (`stock-screener portfolio`) | 全ユニバース + 指数ETF の過去10年の日足 | `reports/portfolio-backtest.md`: 市場ごとに「指数ETF / ユニバース等金額 / モメンタム上位N / +トレンドフィルタ / トレンドのみ」の CAGR・最大DD・シャープ・暦年リターン。入れ替えコスト控除 | 週次 |
| **バックテスト** (`stock-screener backtest`) | ウォッチリスト (または全ユニバース) の過去5年の日足 | `reports/backtest.md`: シグナル種別ごとの +20/+60/+120 営業日後の勝率・平均リターンと、ベースライン (全営業日に買った場合) に対する超過リターン | 週次 (スクリーニング直後) |
| **成績追跡** (`signals` に内蔵) | `data/signal_log.csv` (実際に出したシグナルの台帳) + 最新株価 | `reports/performance.md`: 記録済み新規シグナルの事後リターン | 日次 |

- シグナル判定ロジックは `signals/technical.py` の `compute_signal_frame` に一本化し、全営業日分をベクトル計算する。日次判定はその最終行、バックテストは全行を使うので、**本番で鳴るシグナルと検証するシグナルが必ず一致する**。
- 「エントリー」= シグナル成立日のうち直前 N 営業日 (`renotify_after_days`) に同じシグナルが無かった日。連日成立する押し目を1回と数える。本番の「新規」通知と同じ定義。
- 外部ライブラリ (vectorbt 等) は使わず pandas のみで実装 (依存を増やさない、ルールと検証コードを同一にするため)。
- 価格データの不良値 (yfinance の調整ミスによる一時的な急落→即回復) は `data/prices.py` で検出し前日値で補正する。1306.T で実際に発生した。
- 2026-10-20 時点の結果: 12-1ヶ月モメンタム上位15銘柄の月次保有は日本・米国ともに指数ETFとユニバース等金額を上回る (日本 CAGR +24% vs 指数 +12%、米国 +22% vs +15%)。トレンドフィルタはリターンを下げ最大DDをわずかに改善。テクニカル4シグナルは超過ほぼゼロ。
- バックテストの限界: 対象銘柄が現在の財務指標で選ばれているため生存バイアスが入る。検証対象は主に第2段階のタイミングルール。第1段階の選定効果は `data/fundamentals/` の日付別スナップショットが溜まった後に検証する (Phase 4)。

### ⑦ モデルポートフォリオ (ペーパー運用、Phase 3.5: 実装済み)

バックテストで良かった戦略を「今なにを持つか」の具体的な銘柄リストに落とし、その後の評価額を指数ETFと並べて毎日記録する。注文は出さない。

- 戦略: **モメンタム戦略** (市場別 12-1ヶ月モメンタム上位15、検証済み) と **合成スコア戦略** (市場別 ウォッチリスト上位15、財務指標の前向き検証を兼ねる)
- ルールはポートフォリオ・バックテストと同一 (等金額、月初の最初の実行日に入れ替え、入れ替えコスト控除)。継続保有の銘柄は取得日・取得価格を引き継ぐ
- 状態 (`data/model_portfolio/holdings.csv` / `trades.csv` / `nav.csv`) をリポジトリにコミット。同じ日の再実行は上書き (冪等)
- 位置づけ: バックテスト (過去、生存バイアスあり) → **ペーパー運用 (これから、バイアスなし)** → 実運用、の順に証拠の強さが上がる。半年〜1年分溜まった時点で対指数がプラスなら戦略を続け、マイナスなら見直す

## 技術スタック

| 項目 | 選定 | 理由 |
|---|---|---|
| 言語 | Python 3.12+ | データ分析エコシステムが最強 |
| データ処理 | pandas / polars | 標準的 |
| データ取得 | yfinance, J-Quants API | 無料で多市場カバー |
| 実行基盤 | GitHub Actions (cron) | サーバ不要・無料枠で十分 |
| 通知 | Slack Webhook 等 | 無料・簡単 |

## コスト

**フェーズ1〜3はすべて無料で構築可能。**

| 項目 | 無料構成 | 有料アップグレード(任意) |
|---|---|---|
| 株価・財務データ | yfinance | J-Quants ライト 月1,650円(日本株の鮮度・精度向上) |
| 実行環境 | GitHub Actions 無料枠 | 不要(日次バッチなら余裕) |
| 通知 | Slack 無料プラン | 不要 |

→ まず無料で運用開始し、精度に不満が出た時点で有料データを検討するのが合理的。

## 開発フェーズ計画

| フェーズ | 内容 | 成果物 |
|---|---|---|
| **Phase 1** | データ収集 + ファンダスクリーニング | 週次でウォッチリスト(上位銘柄一覧)が出る |
| **Phase 2** | テクニカルシグナル + 通知 | 買いシグナル発生時に通知が届く |
| **Phase 3** (実装済み) | バックテスト (シグナル別 + ポートフォリオ) + シグナル成績追跡 | 指数に勝てるかが数値で分かる。モメンタムを第1段階に採用 |
| **Phase 3.5** (実装済み) | モデルポートフォリオ (ペーパー運用) | 戦略に従う場合の保有銘柄と、その後の成績 vs 指数が日次で分かる |
| **Phase 4** | 第1段階の検証・改善 | 財務スナップショットが溜まり次第、財務指標による選定を同じ枠組みで検証。保有数・頻度の感度分析。対象市場拡大 |

最初の対象市場は**日本株(東証)+ 米国株(S&P500 + NASDAQ100)**から始め、仕組みが安定してから他市場(欧州・香港等)へ広げる。

## 注意事項

- 本システムは投資判断の**候補を提示する**ものであり、利益を保証するものではない。最終的な投資判断は必ず自身で行うこと。
- yfinance は Yahoo Finance の非公式ライブラリであり、仕様変更で動かなくなるリスクがある(データ収集層を差し替え可能な設計にして緩和する)。
- 無料データには遅延・欠損があり得る。中長期投資では実害は小さいが、認識しておくこと。
